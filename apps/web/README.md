# @petlife/web

React SPA for PetLife. Vite 8, React 19, TanStack Router, Tailwind CSS v4, Base UI. TypeScript, ESM.

## Run

```bash
pnpm dev:web   # from the repo root — Vite dev server on :5173
```

Anything under `/api` needs the api running too (`pnpm dev:api`) — the dev server proxies `/api/*` to `http://localhost:3000` so the browser sees one origin.

Smoke test: `curl http://localhost:5173/api/v1/ping` → `{"status":"ok"}`

## Layout

```
index.html         # the real entry — Vite serves and bundles from here
vite.config.ts     # plugins (Router codegen + splitting, React, Tailwind) + the /api dev proxy
index.css          # Tailwind entry: @theme design tokens + base styles
src/
├─ main.tsx        # creates the router (context carries the auth stub) and mounts <RouterProvider>
├─ auth.ts         # AuthState + the stub the route guard reads — 6.4 swaps in the real session
├─ routeTree.gen.ts# generated by the router plugin — never edit it, always commit it
└─ routes/         # file-based routes: the file name is the URL
   ├─ __root.tsx               # root layout (header/nav shell), 404 page, devtools
   ├─ index.tsx                # /
   ├─ login.tsx                # /login (placeholder until 6.4)
   ├─ register.tsx             # /register (placeholder until 6.4)
   ├─ _authed.tsx              # pathless guard layout — redirects to /login when logged out
   └─ _authed.pets.index.tsx   # /pets (guarded; placeholder until 6.3/6.5)
```

## Conventions

- **Same-origin dev.** The browser talks only to :5173; the dev proxy forwards
  `/api/*` to the api and rewrites the `Origin` header so BetterAuth sees its
  own baseURL. Production gets the same shape from the reverse proxy (Phase 10) — no CORS configuration anywhere.
- **Routes are files.** `src/routes/` is the URL structure: `index.tsx` is the
  directory's exact match, `$param` segments are dynamic, and a leading `_`
  makes a pathless layout (wraps children, adds no URL segment). The Vite
  plugin generates `routeTree.gen.ts` from it; `<Link to>` is typechecked
  against that tree.
- **Route files export `Route` and nothing else.** Page components stay
  non-exported consts in the route file — that is what lets the plugin's
  automatic code splitting extract them into per-route chunks (exporting them
  verifiably defeats it). The plugin owns HMR for these files.
- **Guards live in `beforeLoad`.** Auth checks read the router context and
  `throw redirect(...)`; children of a guarded layout never start loading.
- **Design tokens live in CSS.** Tailwind v4 is configured in `index.css`:
  `@theme` tokens generate the `brand-*`, `gutter` and `display` utilities.
  There is no `tailwind.config.js`.
- **Base UI for behavior, Tailwind for looks.** Headless components own
  semantics and accessibility; every visual decision is utility classes bound
  to tokens.
